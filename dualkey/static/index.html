What Dual-Key found

Every GPU node in the cluster, the model server running on it, and the comparison group it was placed in. Servers running the same model join one group, and a group starts checking once it has 3 ready members.

2

What each part is doing

Test prompts (and optionally real app traffic) are answered by one GPU, queued, re-scored by a different GPU in the same group, and the gap goes to the Detector. Numbers are for the last minute.

3

What the Detector sees

Each GPU gets a score: how far its disagreements with its partners are above normal, in standard deviations. A GPU is flagged only when it disagrees with every partner, so one bad checker can't get a good GPU quarantined.

4

Dual-Key vs the vendor's own monitoring

For each GPU: what NVIDIA's DCGM (or AMD's metrics exporter) and node health tools such as NVSentinel report, next to what Dual-Key concluded. Silent data corruption is the case where the vendor tools stay green while the answers are wrong.

5

Incidents and response

Every quarantine opens an incident: the evidence, what the vendor tools and the vendor's own diagnostic said about the node, what was done to the node, and the re-check after release.
